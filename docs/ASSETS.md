# Как заменить спрайты

Графика лежит в `assets/sprites/`: 25 PNG плюс `manifest.json`. Манифест —
единственный источник правды о геометрии кадров, код читает всё оттуда.

Игра не зависит от наличия PNG: если файла нет, он битый или манифест вообще не
загрузился, рисуется процедурный плейсхолдер из палитры GDD 11.1. Уровень
полностью проходится на плейсхолдерах, ошибок в консоли при этом не возникает.

## Три сценария

| Что нужно | Что делать |
|---|---|
| Заменить существующий спрайт | Положить PNG с тем же именем и той же геометрией кадра поверх старого. **Код и манифест менять не нужно.** |
| Добавить свой спрайт с другим числом кадров | Положить PNG и поправить у этой записи `frames` и `fps` (при другом размере кадра — ещё `frameW`/`frameH`). |
| Убрать спрайт | Удалить PNG. Игра молча нарисует плейсхолдер. Запись в манифесте можно оставить. |

Запись, написанная **ровно по GDD 11.3**, грузит свой PNG — никаких
дополнительных обязательных полей нет.

## Формат манифеста

```json
"player_run": {
  "file": "player_run.png",
  "frameW": 16, "frameH": 16,
  "frames": 4, "fps": 12,
  "loop": true,
  "offsetX": 0, "offsetY": 0
}
```

| Поле | Смысл |
|---|---|
| `file` | имя файла внутри `assets/sprites/` |
| `frameW`, `frameH` | размер одного кадра в пикселях |
| `frames` | количество кадров в ленте |
| `fps` | скорость анимации |
| `loop` | `false` — анимация останавливается на последнем кадре |
| `offsetX`, `offsetY` | сдвиг при отрисовке; позволяет использовать спрайт крупнее тайла (например 16×24) без правки кода |

Необязательное поле `"present": false` — явный опт-аут: загрузчик не станет
запрашивать этот PNG и сразу нарисует плейсхолдер. Пригодится, если файл
заведомо не поставляется и не хочется лишнего запроса. По умолчанию (поля нет)
файл грузится.

## Правила рисования

- Тайл — 16×16 px. Персонажи и предметы тоже 16×16.
- Кадры анимации выложены **горизонтальной лентой** слева направо (1×N кадров).
- Все персонажи рисуются **лицом вправо**; поворот влево делается зеркальным
  отражением в коде, отдельных файлов не нужно.
- Покачивание предметов (±1 px, период 1 с) делает код, а не анимация —
  статичный PNG не сломает вид.
- Враг на трубе использует кадры `*_climb`.
- Дверь: кадр 0 — «закрытая/тусклая», кадр 1 — «подсвеченная». Пока собрано
  меньше 8 продуктов, рисуется только кадр 0.

## Текущий комплект

В репозитории лежит полный набор из 25 файлов, сгенерированный скриптом
`tools/gen-sprites.mjs` (чистый Node, без зависимостей):

```sh
node tools/gen-sprites.mjs     # перерисовывает все 25 PNG в assets/sprites/
```

С уровнем 3 в комплект добавляется 26-й файл — `enemy_ceo_walk.png`,
главный начальник (`docs/LEVEL3.md` п. 11). Кадров лазания у него нет: он не
лазает.

Скрипт — стартовая графика, а не обязательный шаг сборки. Нарисованные вручную
PNG просто кладутся поверх; запускать генератор после этого не нужно, иначе он
перезапишет вашу работу.

## Удалить графику совсем

Достаточно удалить папку `assets/sprites/` целиком — игра продолжит работать
на плейсхолдерах, консоль останется чистой.
